## 11-02

### 当前梳理

这批需求可以先收敛成四条主线，避免后面把“页面形态”、“AI 能力”和“数据边界”混在一起讨论。

#### 1. 整理主线

- 系统需要支持一次全量抓取当前账号下的收藏夹与收藏项。
- 抓取完成后，分析助手可以基于标题、简介等来源数据给出 `归位建议`，帮助用户判断某条收藏项更适合进入哪个收藏夹。
- 这里的核心价值不是“自动移动”，而是“给出可确认的整理建议”。

#### 2. 分析主线

- 系统需要基于收藏夹分布、主题类别和数量变化生成 `偏好画像`。
- 分析结果应以可视化图表呈现，目标是帮助用户理解自己的收藏习惯，而不是只做静态统计表。
- 这部分更适合作为 `工作台` 的主要输出，而不是塞进明细页。

#### 3. 结构与交互主线

- 需要保留一个专门列出全部收藏夹的入口页，方便快速定位目标收藏夹。
- 需要一个 ERP 风格的日常整理主界面，采用左侧收藏夹列表、右侧收藏项明细的双栏结构。
- 为避免和现有 glossary 冲突，这个双栏主界面统一称为 `工作区`，而不是 `工作台`。

#### 4. 特殊来源主线

- `稍后再看` 需要被整合进现有体系，但它更像一个特殊来源容器，不宜直接等同于普通收藏夹。
- 该来源可以在主界面中作为一个特殊节点出现，也可以提供单独页面聚焦展示，目标是强化“尽快消费”和“后续归档”的流程。

### 已收敛的领域词汇

- `工作台`：聚合指标、待整理事项和分析入口的概览页。
- `工作区`：左侧导航加右侧明细的双栏整理界面。
- `收藏夹说明`：用户补充的用途描述，用来解释收藏夹适合承载什么内容。
- `归位建议`：分析助手给出的目标收藏夹推荐。
- `偏好画像`：面向用户习惯理解的图表化分析结果。
- `稍后再看池`：从平台“稍后再看”导入的一组特殊来源项。

### 当前最值得继续澄清的边界

1. `归位建议` 是只给一个推荐结果，还是给多个候选收藏夹并附带理由。
2. `收藏夹说明` 是首次初始化时统一采集，还是只在 AI 无法判断时追问用户。
3. `稍后再看池` 进入系统后，是只承担提醒职责，还是允许转存为正式收藏项。
4. `工作台` 和 `工作区` 是否都要作为一级页面存在，还是一期先落一个主界面。

### 原始想法

1. 整理，对当前的收藏夹进行全量的数据抓取，然后根据视频的标题和描述分析视频的分类，并决定哪个子收藏夹更适合它放进去。
2. 分析，也就是对不同收藏夹的数量以及整体的类别进行分析，生成可视化图表，反映用户的收藏习惯或视频偏好。要有可视化图表分析，方便用户理解自己的收藏习惯。
3. 增加收藏夹描述，也就是简介属性，可以让 agent 问用户，或者根据收藏夹内部细分，用户需要回答收藏夹和用途，方便后续定位细分。
4. 需要有一个页面专门列出这些收藏夹，方便用户找到对应的收藏夹，然后点开看到最终的收藏夹内部页面。
5. 要有一个默认页面，跟 ERP 和现在的页面很像：左侧侧边栏是收藏夹列表，右侧是收藏夹内部的视频。
6. 要把稍后再看的视频，整合到现有的收藏夹体系中，主要是提醒用户尽快观看，也可以提供收藏功能，主收藏夹页要有一个收藏夹稍后再看，也可以另外列出一个页面，专门列出来稍后再看的视频。
