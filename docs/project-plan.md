# 视频收藏后台项目计划

## 1. 目标与边界

### 1.1 项目目标

本项目的目标不是做一个“自动替用户操作平台”的重度运营系统，而是做一个面向个人使用的整理与分析后台，帮助用户更高效地完成以下闭环：

1. 导入账号下的收藏夹与收藏项
2. 补齐关键收藏夹的业务语义
3. 在 `工作区` 中查看收藏项、获取 `归位建议`、确认整理结果
4. 处理中转性质更强的 `稍后再看池`
5. 在后续阶段逐步补齐真实写回平台与偏好分析能力

### 1.2 已确认的硬边界

- 来源数据默认只读，遵循现有 ADR：平台原始字段不在本地随意改写。
- 一期不做真实写回平台，只记录本地确认结果。
- 二期高优先级推进“用户确认后的单条写回平台”。
- 当前阶段是单用户、单账号、非全职投入项目。
- 一期即按前后端分家落地，不继续在 Express + EJS 上叠加主要功能。
- 前端技术方向定为 `React + Ant Design`，后端继续承接内部 API 与聚合逻辑。

### 1.3 一期暂不做

- 平台真实写回
- 批量归位 / 批量转存
- 完整 `偏好画像` 图表页
- 自动全量生成所有建议
- AI 自动决定关键收藏夹
- 多账号 / 多租户
- 自动同步 / 定时同步
- 复杂权限和协作能力
- CLI 独立产品化

## 2. 产品结构与领域主线

### 2.1 页面结构

#### 工作区

`工作区` 是默认首页，也是一期唯一的主操作界面。

- 左侧：`稍后再看池 / 关键收藏夹 / 普通收藏夹`
- 右侧：当前选中容器下的收藏项表格
- 辅助区域：`收藏夹说明`、`归位建议`、轻量统计

#### 全部收藏夹列表页

保留为二级页面，用于快速浏览全部收藏夹和检查容器结构，但不作为默认首页。

#### 工作台

后置到三期，只负责概览、图表、待办与入口，不承载详细整理操作。

### 2.2 需求主线

#### 主线 A：整理

- 全量导入当前账号下的收藏夹与收藏项
- 关键收藏夹录入半结构化 `收藏夹说明`
- 按需触发 `归位建议`
- 用户在工作区内确认建议结果并写入本地

#### 主线 B：特殊来源处理

- 把 `稍后再看池` 纳入统一工作区
- 支持提醒、单条转存、待处理状态管理
- 转存后移出待处理视图，但保留来源记录

#### 主线 C：后续写回平台

- 二期开始支持“人工确认后的单条写回平台”
- 写回失败时保留本地确认结果，并明确标记为未同步

#### 主线 D：分析

- 一期只做当前容器范围内的轻量统计与整理提示
- 三期再补完整 `工作台`、`偏好画像` 与图表分析

## 3. 特性优先级

### P0：一期必须完成

- 前后端分家基础结构
- 内部 API
- 本地数据库
- 全量导入链路
- 初始化流程
- `工作区` 主界面
- `稍后再看池` 接入
- 半结构化 `收藏夹说明`
- `归位建议` 生成与本地确认闭环
- 当前容器范围内的轻量统计

### P1：二期高优先级推进

- 用户确认后的单条写回平台
- 写回状态记录与失败标记
- 更稳的建议质量与重试流程
- 更完整的同步状态可视化

### P2：三期补齐

- `工作台`
- `偏好画像`
- 图表分析
- 更系统的整理待办视图
- 收藏夹目录页与分析页之间的入口联动

### P3：后续派生方向

- CLI 工具
- 更多分析维度
- 更复杂的批量整理能力
- 多账号与长期同步能力

## 4. 一期实施计划

### 4.0 前置动作：引入版本控制

在做任何结构调整之前，先为仓库建立版本控制基线。

原因是时机问题：一期最重的工作恰恰是整个项目风险最高的动作——把 `app.js` 拆进
`apps/server`、引入本地数据库、再让 React 接管首页。这类改动的特征是「改完才知道对不对」，
如果没有可回退的已知良好状态，整个迁移过程等于没有安全网。
而当前原型链路刚验证通过，正是存档的最佳时机，所以版本控制应该排在重构**之前**，而不是之后。

- 完成标准：仓库存在一个可回退的基线提交，且 `.env` 等凭据文件已被正确忽略
- 顺序约束：先于迭代 1 的任何代码搬迁

### 4.1 周期基线

一期按单人、非全职投入估算，先以 **3 个两周迭代** 作为计划基线。

### 4.2 迭代拆分

#### 迭代 1：前后端分家底座与初始化流程

目标：

- 建立前后端分家结构
- 引入本地数据库
- 跑通来源数据导入
- 跑通首次初始化流程

交付内容：

- React 前端工程与基础布局
- 后端内部 API 分层
- 本地增强数据表结构
- 全量导入接口
- 关键收藏夹勾选流程
- `收藏夹说明` 录入表单

验收标准：

- 用户可以完成一次全量导入
- 用户可以勾选关键收藏夹
- 用户可以为关键收藏夹录入说明
- 初始化完成后能进入 `工作区`
- 数据可持久化保存，刷新后不丢失

#### 迭代 2：工作区主链路与稍后再看池

目标：

- 让 `工作区` 成为真正可用的日常整理界面
- 接入 `稍后再看池`
- 跑通本地确认闭环

交付内容：

- 左侧导航分区：`稍后再看池 / 关键收藏夹 / 普通收藏夹`
- 右侧收藏项表格
- 容器级轻量统计
- `稍后再看池` 的单条转存
- 建议状态记录：`待确认 / 已确认目标收藏夹 / 暂不处理`

验收标准：

- 默认首页即 `工作区`
- 左侧容器分区清晰可用
- 右侧表格可浏览当前容器的收藏项
- 稍后再看条目可以单条转存
- 本地确认状态可保存并可回显

#### 迭代 3：归位建议闭环与稳定性打磨

目标：

- 提升 `归位建议` 的可用性
- 补齐一期范围内的整理闭环
- 为二期写回平台预留接口边界

交付内容：

- 3 个候选收藏夹的 `归位建议`
- 每个候选的短理由与命中依据标签
- 建议按需触发
- 写回平台相关的同步状态模型预留
- 错误提示、空态、异常链路打磨

验收标准：

- 当前容器内的收藏项可按需生成建议
- 每条建议都包含 3 个候选及理由
- 用户可确认目标收藏夹或标记暂不处理
- 界面能清晰区分本地确认结果与平台同步状态
- 一期范围内不依赖真实写回平台也能形成可用闭环

## 5. 一期功能规则

### 5.1 初始化流程

首次初始化固定采用以下顺序：

1. 导入全部来源数据
2. 用户勾选关键收藏夹
3. 为关键收藏夹填写轻量 `收藏夹说明`
4. 进入 `工作区`，优先处理 `稍后再看池` 与待整理项

### 5.2 收藏夹说明规则

`收藏夹说明` 在一期初始化阶段先采用轻量输入，只要求用户写一句“这个收藏夹主要用来干什么”。

更细的结构化字段（主要放什么 / 明确不放什么 / 典型关键词）先保留在数据模型里，
后续接入 Agent 后再根据收藏夹内容自动草拟，由用户微调确认。

关键收藏夹只有在这句用途说明填写完成后，才参与 `归位建议`。

### 5.3 归位建议规则

- 按需触发，不在导入后自动全量生成
- 采用“规则优先，AI 辅助”的混合策略
- 每条建议默认给出 3 个候选收藏夹
- 每个候选提供短理由与命中依据标签
- 一期仅记录本地确认结果，不直接调用平台移动收藏项

### 5.4 建议状态最小集

- `待确认`
- `已确认目标收藏夹`
- `暂不处理`

### 5.5 稍后再看池规则

- 作为特殊来源容器，不等同普通收藏夹
- 一期支持单条转存与基础待处理状态
- 转存后移出待处理视图，但保留来源记录

## 6. 二期与三期规划

### 6.1 二期：真实写回平台

二期主线是高优先级推进“人工确认后的单条写回平台”。

范围：

- 用户确认后的单条执行
- 同步状态记录
- 写回失败提示
- 基础重试能力

明确不做：

- 自动执行
- 批量执行
- 无确认直接写回

交付标准：

- 用户可以对单条已确认结果发起写回
- 写回成功与失败都有清晰反馈
- 失败后本地确认结果仍保留
- 系统可明确标记“已同步 / 未同步”

### 6.2 三期：工作台与偏好画像

三期主线是补齐概览层和分析层能力。

范围：

- `工作台`
- `偏好画像`
- 图表分析
- 待办与入口聚合

交付标准：

- 用户可以在 `工作台` 看到整体概览与待办入口
- 用户可以查看收藏习惯与偏好图表
- `工作台` 与 `工作区` 的职责清晰，不互相覆盖

## 7. 最小数据模型建议

一期至少需要稳定持久化以下本地增强数据：

- 收藏夹说明
- 关键收藏夹标记
- 归位建议结果
- 建议确认状态
- 稍后再看池处理状态
- 平台同步状态预留字段

这些数据应与来源数据分开存储，来源数据继续作为只读事实存在。

## 8. 风险与护栏

### 8.1 外部 API 波动

- 不把平台写回放在一期
- 把写回能力独立到二期
- 显式区分“本地确认成功”和“平台同步成功”

### 8.2 AI 结果不稳定

- 采用“规则优先，AI 辅助”
- 建议只给候选，不自动执行
- 关键收藏夹先补说明，再参与建议

### 8.3 单人项目范围失控

- 明确一期暂不做清单
- 一期只围绕 `工作区` 主链路交付
- 分析能力后置到三期

## 9. 当前执行顺序建议

如果下一步进入真正开发，推荐按下面顺序推进：

1. 设计前后端目录结构与内部 API 边界
2. 设计本地数据库最小模型
3. 搭建 React + Ant Design 工作区骨架
4. 接入初始化流程
5. 接入收藏项表格与左侧容器导航
6. 接入收藏夹说明与归位建议
7. 接入稍后再看池与本地确认闭环
8. 最后补轻量统计与错误处理
